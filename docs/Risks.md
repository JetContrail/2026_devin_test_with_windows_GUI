# リスク一覧

影響度・発生可能性: 高 / 中 / 低

| ID | リスク | 影響 | 可能性 | 対策 | 関連 |
|----|----|----|----|----|----|
| R1 | WPF は Windows 専用のため、Linux 等の開発環境では UI を実行・テストできない | 中 | 高 | ロジックを WPF 非依存の Core に集約。Core テストは全 OS で実行し、UI/Infrastructure テストは Windows CI で実行。`EnableWindowsTargeting` で全 OS ビルド可能にする | #2 #5 |
| R2 | 大きな下絵 (4K 以上) で Undo 履歴がメモリ 300MB を超える | 高 | 中 | 変更矩形の差分パッチのみ保持し Deflate 圧縮。履歴にバイト上限を設けて古い履歴から破棄 (20操作は保証) | #16 #22 |
| R3 | 高速ドラッグ時に線が途切れる / 描画が遅延する | 中 | 中 | 前回点との線分補間、差分矩形のみ WriteableBitmap へ転送 | #6 #7 |
| R4 | 高倍率 (800%) 時の描画負荷・ぼやけ | 中 | 中 | `RenderOptions.BitmapScalingMode=NearestNeighbor`、ビューポート変換のみで再ラスタライズしない | #17 |
| R5 | オートセーブ中の UI フリーズ / 書込み中断によるファイル破損 | 高 | 中 | UI スレッドではピクセルのスナップショット取得のみ、エンコード・書込みはバックグラウンド。一時ファイルに書いてからリネーム | #19 |
| R6 | オートセーブフォルダの肥大化 | 中 | 低 | 10 世代を超えた古いデータを保存直後に削除。変更が無ければ保存スキップ | #19 |
| R7 | 下絵画像の形式不正・巨大画像による例外・OOM | 高 | 中 | デコード例外をアプリ層で捕捉しエラー表示。最大ピクセル数 (例: 8192x8192) を超える場合は拒否 | #12 |
| R8 | DPI / 色空間の違いで保存結果のサイズ・色がずれる | 中 | 中 | 読込時に 96DPI・BGRA32 に正規化し、ピクセル単位で管理 | #12 #13 |
| R9 | 将来の複数レイヤー・図形・テキスト追加で大規模改修が必要になる | 中 | 中 | Layer/LayerStack、ITool、IImageEncoder の抽象を初期から導入 (Architecture.md 拡張ポイント参照) | #11 #13 |
| R10 | カバレッジ 80% 未達 (UI コードが多い) | 中 | 中 | ViewModel にロジックを集約し View はバインディングのみ。計測対象から XAML View を除外 | #20 |
| R11 | 100回繰り返し操作でのリソースリーク (イベント購読・ビットマップ) | 高 | 低 | 耐久シナリオテストを自動化し、メモリ増加量を検証 | #21 |
| R12 | .NET 10 SDK / パッケージ更新による CI 不安定化 | 低 | 中 | `global.json` で SDK を固定、`Directory.Packages.props` で版数を一元管理 | #2 #5 |
| R13 | 要求の曖昧さ (下絵再読込時の描画の扱い等) による手戻り | 中 | 中 | 仮定を ProductBacklog.md と各 Issue/PR に明記し、早期にレビューを受ける | 全体 |
